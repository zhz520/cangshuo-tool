# 工具开发与开源参考约定

用户要求：以后每个工具的开发与修复都参考 GitHub 已有优秀代码，功能应覆盖实际使用需求，逻辑与异常处理完整，并将依据写入工具文档。

## 1. 开始前

1. 阅读项目规格、路线图、AGENTS；Android 界面同时阅读 UI 规范。
2. 检查已有实现和可复用组件，确定本轮单个工具的范围。
3. 选择业务相关的优秀开源项目，阅读实际处理逻辑和交互。DevToys、CyberChef、IT-Tools 是候选，Android、图片、二维码等场景优先增加对应平台的专项实现。
4. 不以项目名称、README 功能宣传或截图代替源码研究。查阅失败时记录实际限制，使用可取得的相关源码和官方资料继续工作。

## 2. 参考记录

每个工具的 `docs/<工具名>.md` 必须包含：

| 项目 | 内容 |
| --- | --- |
| 来源 | 仓库、具体源码/设计链接、查阅日期；能确认时记录 tag/commit |
| 采用内容 | 实际借鉴的算法、格式规则、流程、交互和错误处理 |
| 适配差异 | Android/服务端差异、离线要求、资源限制、架构边界及主动舍弃的行为 |
| 功能覆盖 | 核心操作、选项、输入/输出、复制/保存/分享及当前不支持范围 |
| 边界处理 | 非法输入、空值、极值、编码、区域/时区、资源上限、并发、取消、失败重试 |
| 验证 | 实际执行的构建/Lint/检查结果；自动测试和设备验证若未执行必须明确说明 |

引用源码的固定提交或版本时必须核实；仅查阅分支源码时明确它是可变化的链接。参考项目的技术选择不自动成为本项目依赖或执行规范。

## 3. 功能与逻辑标准

- 按完整工作流程设计：输入 → 选项 → 处理 → 状态/错误 → 查看结果 → 复制/保存/分享；只提供相关且真实可用的操作。
- 输入格式、精度、舍入、编码、时区及输出语义明确；不默默改写用户数据，不把截断结果当作完整结果。
- 在昂贵计算、图片解码或内存展开前检查资源预算；避免只在处理结束后检查长度/大小。
- 后台处理支持取消；旧任务不得覆盖新输入。同步原生操作不能假设取消立即中断，应限制并发并检查结果归属。
- 保存和分享传递实际处理结果；出现错误时退出加载、给出可操作的本地化提示，并清理未完成产物。
- 中文为主要回退语言，默认跟随系统；英语同步维护，界面不显示原始异常或硬编码业务文案。
- Android 复用主题和共享加载组件，保持 UI → ViewModel → UseCase → Repository。
- 明确不支持的内容，例如动画帧、超大图片、原始元数据保留；不把有限实现描述成支持所有情况。

## 4. 网页版工具承载规则

用户于 2026-10-04 确定：工具可以采用官网网页版实现。代码复杂、依赖或资源会显著增加 APK 体积时，优先评估该方式；简单、离线优先或涉及敏感本机数据的功能继续原生实现。判定、模式和完整约束见 `toolbox-vibe-spec/PROJECT_SPEC.md` Decision 019。

- 域名与路径：正式环境 `https://tool.zhzgo.cn/tools/<tool_code>/`，本地开发 `http://localhost:8088/tools/<tool_code>/`；`<tool_code>` 与 ToolRegistry 编码一致，一个工具一个目录，静态资源使用相对路径。
- App 打开：应用内 WebView 容器，使用系统 WebView（Chrome 内核）；不默认跳外部浏览器；WebView 不可用、无网络、证书或加载失败时显示本地化错误、重试和返回。
- 目录与模式：仍需唯一 code、完整元数据和 ToolRegistry 注册；模式规划为 `WEB`。首个网页版工具实现时必须同步 Android `ToolMode`、DTO、界面标签、Server 枚举/校验、`tool_definition.mode` CHECK 的 Flyway 迁移、`config_json` 网页路径以及 API/数据库/目录文档，不能只在客户端写死 URL。
- 安全：正式环境仅 HTTPS；WebView 只加载白名单域名，重定向同样受约束；关闭文件/内容访问与 `addJavascriptInterface`；不通过 URL 传递 Token、密码或敏感原文；网页端不得记录敏感数据。
- 隐私与体验：打开前标注“网页版 · 数据将在 tool.zhzgo.cn 处理”；首屏加载复用共享加载组件；系统返回键先回退网页历史；保持中文/英语提示与可访问性。
- 文档与验证：网页版工具的 `docs/<工具名>.md` 需记录网页实现范围、部署路径、参考源码、域名白名单、权限、隐私说明、失败/离线行为以及实际构建和浏览器/设备验证；未部署或未验证的范围必须明确写出。

## 5. 代码与交付

- 参考思路后按项目架构实现；复制或改编第三方代码时核对许可证并保留所需署名。不能确认的许可不作为复制依据。
- 不因参考项目使用某个依赖而自动升级或引入它；新增依赖需与本轮目标直接相关。
- 每次完成一个路线图任务，同步工具文档、路线图及必要的交接/审查进度。
- 构建通过不等于功能全部通过；清楚区分静态判断、构建/Lint、样例检查、自动测试和设备验收。
- 提交前清理本轮临时文件，保留其他任务已有工作；新建和生成文件遵守 D 盘保存规则。

## 6. 工具文档建议结构

1. 定位、唯一 code、分层与运行方式。
2. 开源参考表与适配决策。
3. 已实现功能和当前不支持范围。
4. 输入输出规则、资源与权限边界。
5. 并发、取消、错误与恢复策略。
6. 界面、多语言、加载和可访问性。
7. 本轮变更与实际验证结果。
8. 后续验收清单与剩余工作。

2026-10-04 起按此约定执行。已有工具文档在对应工具的后续修复中逐一补足，不将尚未完成的参考研究补写成已执行。
