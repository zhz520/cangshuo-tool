# 管理后台 UI 重写方案

制定日期：2026-10-06。UI-1–UI-5 页面迁移已实施，2026-10-11 首次部署通过。用户随后要求改用 OpenAI Platform 风格的浅色控制台；当前视觉、组件和布局以 [控制台设计系统](ADMIN_CONSOLE_DESIGN_SYSTEM.md) 为准。以下章节保留原截图方案及当时的实施验收历史，不再作为当前颜色和尺寸规范。真实业务联调与完整无障碍验收另行进行，部署与回退见 [正式部署记录](ADMIN_UI_DEPLOY_2026-10-11.md)。

## 1. 目标与依据

将后台统一为「近黑工作台 + 灰白信息层级 + 荧光绿操作重点」的视觉风格。优先改善导航辨识、列表阅读、表单处理和手机操作，沿用 Vue 3、TypeScript、Element Plus、Pinia、Vue Router 与集中 API 模块。

用户参考图：`695264ed6c44ca7109541b5a002c8cbb.jpg`，2026-10-06 随本次请求提供。图中可直接观察到近黑侧栏、灰色线性图标、白色选中项、左侧荧光绿指示条、浅色数量胶囊和较宽的菜单间距。右侧内容被压暗，推断为导航打开后的遮罩；这不是正常工作区的文字对比度标准。截图主要展示导航，正文表格、弹窗、浅色主题为本方案补充设计，不能称为原图复刻。

采用视觉语言，品牌使用「沧烁工具箱 / ADMIN」，保留项目现有功能命名与路由。截图中的 Z³ 标识、351 数字、注册邀请、云端用量、发版和群体权重不作为本项目功能或真实数据。

## 2. 现状与优先问题

| 现状 | 重写要求 |
| --- | --- |
| 深绿色导航、浅绿概览、白色表格/弹窗同时存在 | 建立整套主题，覆盖正文和浮层；不能只把侧栏改黑 |
| 颜色与页面布局集中在 `main.css`，业务页有大量固定宽度 | 拆分主题、组件映射、布局和通用页面样式；业务页面使用语义变量 |
| 表格字段密集，正文和次要信息层级接近 | 主信息优先，辅助字段移到详情，保留完整字段可达性 |

| 工具/分类/反馈等 Dialog 固定 560–720px | 复杂表单使用响应式右侧抽屉；手机占满可用宽度，保留标题和操作区 |

| 登录页含较长的部署与日志说明 | 保留账号、密码、必要错误与操作提示；技术说明留在开发文档 |

以上为本次源码检查结果，没有对实际运行后台做全面视觉验收。

## 3. 视觉规范

默认深色，登录页与正文统一。提供浅色切换，选择只保存在后台浏览器的独立 UI 偏好中，不与管理员令牌键或 Android 设置混用。首屏读取偏好后再绘制，避免闪出白底；无法读取时使用默认深色。

### 排版与尺寸

- 使用本机系统中文字体，不下载字体；页面标题 26px/600、分区标题 18px/600、正文/表格 14px、辅助信息 12px。数量、ID 和时间采用等宽数字。
- 桌面侧栏 248px，折叠为 72px；菜单行高 48px、图标 20px、左右内距 20px、选中指示条 3px。原图是放大的局部参考，不照搬为超大字体导航。
- 顶栏 64px；正文桌面留白 28px，手机 16px；间距使用 4/8/12/16/24/32px。
- 控件高 36px；手机主要触控目标至少 44px。输入圆角 8px、容器圆角 10px、状态胶囊完全圆角。
- 表格默认行高约 56px，紧凑密度约 44px；以文字换行和可点击范围为底线，不强制裁切长内容。
- 荧光绿集中在选中条、一个主要操作和键盘焦点。取消大面积绿色卡片、装饰渐变、发光和悬浮上移。
- 普通反馈动画 120–180ms，抽屉约 200ms；支持 `prefers-reduced-motion`，不人为等待。

### Element Plus 映射

把 primary、背景、文字、边框、填充、disabled、overlay、success/warning/danger/info 一起映射到 `--el-*`。同步覆盖 Table、Input、Select、Button、Switch、Pagination、Dialog、Drawer、Dropdown、Tooltip、MessageBox、Loading 与表单错误。荧光绿 primary 按钮单独使用深色文字，不能沿用默认白字。

主题变量定义在 `html`，而非只放在布局容器中，保证 teleport 到 body 的下拉、抽屉和确认框仍正确继承。删除旧硬编码规则后再做兼容覆盖，避免叠加多个主题互相争夺优先级。

## 4. 布局与导航

工作区结构：左侧导航 → 顶栏 → 页面标题与主要动作 → 筛选 → 内容 → 分页。

| 导航组 | 入口及现有路由 |
| --- | --- |
| 工作台 | 概览 `/dashboard` |
| 工具与内容 | 工具 `/tools`、分类 `/categories`、推荐位 `/banners`、公告 `/announcements` |
| 用户与反馈 | 用户 `/users`、反馈 `/feedback` |
| 平台 | 操作日志 `/logs`、系统配置 `/system-config`（未开放） |

保持 `/banners` 等既有路径，以免破坏书签与部署回退。分组名弱化，图标使用已有 `@element-plus/icons-vue` 的统一线性风格，既有图标不新增库。系统配置标注「未开放」；其余已实现入口正常呈现。概览和侧栏从同一份导航元数据读取 availability。

桌面只在小屏/用户折叠时收起侧栏，不在正常工作区加遮罩。顶栏保留面包屑、真实健康状态、主题切换、管理员昵称/角色与退出；没有接口支持的通知中心、全局搜索、组织切换不显示。

数量胶囊只代表定义明确的真实数量。反馈角标若启用，读取现有反馈接口 `status=PENDING&page=1&pageSize=1` 的 `total`，代表全部待处理反馈；导航懒加载，失败隐藏角标，成功后更新，不循环轮询。不能从当前页推算总数、把全部反馈数伪装成待处理数，或照搬 351。状态标签默认不附分状态数量；后续若增加数量，需独立获取各状态总数。

## 5. 公共组件与交互

| 组件建议 | 责任 |
| --- | --- |
| `AdminPageHeader` | 标题、必要的一句说明、主动作；替代各页重复标题区 |
| `AdminFilterBar` | 搜索、既有筛选、查询/重置；只负责布局，不直接请求 API |
| `AdminDataPanel` | 内容边框、loading/empty/error/retry 区域；保留各页强类型 ElTable，不制作万能 CRUD 配置引擎 |
| `AdminStatusTag` | 状态的文本、语义色和样式，具体状态映射由页面传入 |
| `AdminDetailDrawer` | 标题、正文、操作 footer、响应式宽度、关闭和焦点恢复；业务表单留在页面 |
| `AdminEmptyState` / `AdminErrorState` | 区分空数据、筛选无结果和失败，保留重试与可复制 traceId |

筛选变更返回第一页；浏览详情不重置关键词与分页。刷新保留已有行并标注进行中，失败保持旧内容并说明尚未更新。提交中禁用重复提交，失败保留表单；更新成功再同步对应行/列表，不对失败操作显示成功。

列表主列允许两行摘要，完整内容在详情中查看。危险操作进入明确确认框，显示对象与结果。普通行操作优先「查看/编辑」一个入口；低频动作放更多菜单，移动端动作仍可达。

| 分类 | 分类名/code、说明、真实工具数、排序和启用状态；轻量编辑面板 | 创建/编辑、启停、关联工具删除限制和错误提示 |

| 公告 | 标题、级别、发布/草稿与时间窗；正文编辑保留纯文本 | 新增/编辑、发布/下线、删除、显示窗口 |
| 操作日志 | 模块/结果/关键词筛选、时间优先、请求路径详情，审计结果配文本 | 只读列表、真实分页及全部现有字段，不新增删除日志操作 |
| 概览 | 缩减大面积健康 hero，保留真实连接/耗时/最近检查与可用快捷入口 | 健康请求、重试、traceId 复制；没有统计 API 时不绘制 DAU/收入/使用趋势 |
| 登录、404、未开放 | 与工作区同主题，登录只保留必要表单与错误；统一空/错误页 | 登录限流提示、redirect、鉴权守卫、退出和部署路径 |

反馈文档有措辞不一致：ROADMAP 与旧页面说明使用「回复一次」；`docs/ADMIN_FEEDBACK.md` 和实际 Repository 都允许非空新回复覆盖旧文本、更新时间，不支持清空。重写按实际契约保留可编辑回复，不自行增加只能回复一次的限制；迁移样板页时同步纠正文案，并核对相关测试。

## 7. 响应式与可访问性

- ≥1280px：完整侧栏与常规列表；960–1279px：允许折叠侧栏，正文留白缩小，详情抽屉不覆盖全屏。
- <960px：顶部菜单打开左侧导航抽屉，宽 `min(300px, 86vw)`，正文只在抽屉打开时被半透明黑遮罩压暗。点击遮罩/关闭按钮/Escape 可关闭，锁定底层滚动并恢复触发按钮焦点。
- <640px：标题与操作换行，筛选纵向排列；反馈/用户等显示摘要卡片，详情与编辑占满可用宽度。桌面列字段在详情仍全部可见；确需横向表格时只允许数据区滚动，不能把整个页面撑宽。
- 抽屉和对话框复用 Element Plus 焦点管理，提供标题/aria-label；折叠菜单提供完整名称，不只依赖悬停 tooltip。
- 验收至少覆盖 1440、1280、1024、768、390、320px，以及 200% 缩放、键盘和减少动画。
- 正文目标对比度 ≥4.5:1，关键非文本控件 ≥3:1；分隔线不是唯一辨识方式。预览的部分 token 计算结果在实际验证章节记录，完整组件仍需实施后核验。

## 9. 验证与回退

每个实施任务执行 `npm.cmd run typecheck`、`npm.cmd run build`，保持 `/admin/` 基础路径、深层刷新和 API 地址可用。使用浏览器覆盖桌面/手机、深浅色、登录到期、401/403/429、网络失败、空结果、长内容、打开/关闭抽屉和提交失败。纯样式不增加镜像实现的测试；涉及状态/异步归属/偏好解析时增加有意义的回归。

业务回归按页面范围运行已有 `scripts/check_admin_*.py`；只影响样式时不启动无关全量服务测试。API 脚本通过不能代替界面操作验收。真实写入回归使用明确的临时数据与既有清理流程，不在真实账号上随意执行。

每个任务独立小提交；主题/公共组件与业务页迁移按上述顺序隔离。需要回退时使用对应任务提交，保留认证、数据库及现有部署配置。
