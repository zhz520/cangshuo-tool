- 工具编码：`scoreboard`
- 分类 / 模式：`LIFE` / `LOCAL`
- 排序：624
- 数据迁移：`V72__seed_scoreboard_tool.sql`
- 分层：Compose → `ScoreboardViewModel` → `ScoreboardUseCases` → `ScoreboardRepository`

面向两人、两队或两组活动的通用记分板。比分、队名、节次、计时和操作历史只保存在本机；不登录、不联网，也不上传比赛数据。

## 计分与历史

- 左右双方各自记录 0–999 分；加号和减号按钮使用当前选择的 1、2 或 3 分步长。
- 减分不会低于零；比分可直接点按并在 0–999 范围内修正。
- 每次有效计分、直接修正、交换双方、进入下一节和改队名都会生成一条可撤销记录；最多保留最近 50 条，页面默认显示 20 条。
- “撤销上一步”恢复操作前的比分、队名和节次。恢复后对应记录从历史中移除，继续保持上一操作可撤销。
- “交换双方”同时交换两队名称与比分，但不改变节次和计时。
- “下一节”需要确认；比分归零、队名和计时保留、节次加一，并可通过撤销恢复。
- “重置记分牌”需要红色危险操作确认；清空比分、节次、计时和全部历史，保留队名、步长与常亮偏好。

## 计时

- 秒级递增计时，支持开始、暂停、继续和计时归零；归零后若仍在计时，会从归零点继续。
- 使用 `SystemClock.elapsedRealtime()` 单调时钟计算运行区间，暂停后不会继续增长；页面进入后台时停止刷新，返回时一次性追赶真实已运行时长。
- 恢复时同时比较单调时钟差与持久化时刻的墙钟差。二者相差不超过 2 秒时采用更稳定的单调时钟；设备重启使单调时钟归零或跳变时改用墙钟差，避免误加数十秒或直接跳到上限。墙钟被手动大幅调整时，恢复区间以调整后的墙钟差为准。
- 显示与持久化上限为 `99:59:59`，超过后视觉值停在上限，不溢出布局。
- 计时归零也需要确认，但不会清空比分、节次或操作历史。

## 保存与边界

- 当前状态、计时锚点、步长、常亮偏好及撤销快照写入 `SavedStateHandle`，可恢复旋转、系统重建和离开工具页后重新进入的状态。
- 快照使用版本前缀、固定字段、Base64 URL 文本与逐条校验；损坏、未知动作或越界记录会被单独忽略。它不是独立比赛数据库，系统彻底结束任务、强制停止或清除应用数据后不承诺保留。
- 队名最多 24 个 Unicode 码点；输入阶段保留空格，保存时去除首尾空白，空名称回退到原名称。控制字符和双向格式字符会被过滤，emoji 不会被拆成半个代理项。
- 比分 0–999，节次 1–99，历史 50 条；没有隐藏的“达到分数自动结束比赛”规则。
- 不提供音频、暂停菜单、犯规、局分、发球权、比赛规则模板、云同步、多设备观战、后台常驻通知或屏幕方向锁定。
- “保持屏幕常亮”只影响当前页面可见时的窗口标志，离开页面立即释放；它不是前台服务。

## 界面与可访问性

- 沿用工具详情页的外层骨架，并使用 `ToolGroupCard`、`ToolboxButton`、`ToolboxOutlinedButton`、`ToolboxTextField`、`ToolboxSwitch`、`ToolboxBadge` 和 `ToolResultRow` 等共享组件。
- 比分使用主题 `onSurface` 文本和 130ms 淡入缩放变化；无配色团队偏置、渐变、重阴影或常驻装饰动画。
- 比分与队伍名称具有合并语义，读屏会读出队名、分数和“点按修正”；分数变化使用 polite live region。
- 所有按钮保持 Compose 原生 48dp 触控区；加减按钮、计时、换边、下一节与撤销在主屏可直接访问。
- 中文和英文资源完整；新增文案无硬编码颜色、圆角或业务字符串。
